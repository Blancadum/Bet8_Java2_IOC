1. Herencia

La herencia permite que una clase hija reutilice el código de una clase padre. La hija hereda atributos y métodos, y puede añadir los suyos propios o modificar los existentes.

Se expresa con la palabra clave extends.

// Clase padre (superclase)
public class Animal {
    protected String nombre;
    protected int edad;

    public Animal(String nombre, int edad) {
        this.nombre = nombre;
        this.edad   = edad;
    }

    public void comer() {
        System.out.println(nombre + " está comiendo.");
    }

    public void dormir() {
        System.out.println(nombre + " está durmiendo.");
    }
}

// Clase hija (subclase) — hereda todo de Animal
public class Perro extends Animal {
    private String raza;

    public Perro(String nombre, int edad, String raza) {
        super(nombre, edad);   // inicializa los atributos del padre
        this.raza = raza;
    }

    public void ladrar() {    // método propio de Perro
        System.out.println(nombre + " está ladrando.");
    }
}

// Uso
Perro p = new Perro("Rex", 3, "Labrador");
p.comer();    // heredado de Animal → "Rex está comiendo."
p.dormir();   // heredado de Animal → "Rex está durmiendo."
p.ladrar();   // propio de Perro  → "Rex está ladrando."
Regla: usa herencia cuando la relación es "es un". Un Perro es un Animal. Un Admin es un Usuario.

Sobreescritura de métodos (@Override)

La hija puede redefinir un método del padre para cambiar su comportamiento:

public class Gato extends Animal {

    public Gato(String nombre, int edad) {
        super(nombre, edad);
    }

    @Override
    public void comer() {
        // comportamiento distinto al del padre
        System.out.println(nombre + " come con mucha delicadeza.");
    }
}

Gato g = new Gato("Misu", 2);
g.comer();   // "Misu come con mucha delicadeza." — versión de Gato
@Override no es obligatorio, pero es buena práctica: avisa al compilador de que estás sobreescribiendo un método del padre, y da error si te equivocas en el nombre.

2. super — acceder al padre desde la hija

super es una referencia directa a la clase padre. Se usa en dos situaciones:

UsoPara qué sirve
super()Llama al constructor del padre para inicializar sus atributos
super.metodo()Ejecuta el método del padre dentro del método sobreescrito
public class Admin extends Usuario {
    private String departamento;

    public Admin(String nombre, String departamento) {
        super(nombre);                 // constructor del padre
        this.departamento = departamento;
    }

    @Override
    public void mostrarInfo() {
        super.mostrarInfo();           // ejecuta el método del padre primero
        System.out.println("Departamento: " + departamento);
        System.out.println("Rol: Administrador");
    }
}
Importante: si el padre tiene constructor con parámetros, super(...) debe ser la primera línea del constructor de la hija. Si no, el compilador da error.

3. Composición

La composición consiste en que una clase contiene objetos de otras clases como atributos, en lugar de heredar de ellas.

Se usa cuando la relación es "tiene un": un Coche tiene un Motor. Un Jugador tiene un Inventario.

// Clase independiente — no extiende nada
public class Motor {
    private int cilindrada;
    private String tipo;

    public Motor(int cilindrada, String tipo) {
        this.cilindrada = cilindrada;
        this.tipo       = tipo;
    }

    public void arrancar() {
        System.out.println("Motor " + tipo + " arrancando...");
    }

    public String getInfo() {
        return cilindrada + "cc - " + tipo;
    }
}

// Coche TIENE un Motor (composición)
public class Coche {
    private String marca;
    private Motor motor;     // atributo de tipo Motor

    public Coche(String marca, int cilindrada, String tipoMotor) {
        this.marca = marca;
        this.motor = new Motor(cilindrada, tipoMotor);   // crea el Motor interno
    }

    public void arrancar() {
        motor.arrancar();    // delega en el Motor
        System.out.println(marca + " en marcha.");
    }

    public void mostrarInfo() {
        System.out.println(marca + " — Motor: " + motor.getInfo());
    }
}

// Uso
Coche c = new Coche("Toyota", 1600, "Gasolina");
c.arrancar();     // Motor Gasolina arrancando... / Toyota en marcha.
c.mostrarInfo();  // Toyota — Motor: 1600cc - Gasolina

4. Herencia vs Composición

HerenciaComposición
Relación"es un" (Perro es un Animal)"tiene un" (Coche tiene un Motor)
Palabra claveextendsAtributo de la otra clase
FlexibilidadMenos flexible (acoplamiento fuerte)Más flexible (fácil de cambiar)
ReutilizaciónReutiliza toda la clase padreReutiliza solo lo que necesitas
Regla práctica: si dudas entre herencia y composición, elige composición. Es más flexible y genera menos dependencias. Usa herencia solo cuando la relación "es un" sea clara y estable. 
// MAL — herencia forzada que no tiene sentido real
public class Coche extends Motor { ... }   // un Coche NO ES un Motor

// BIEN — composición
public class Coche {
    private Motor motor;                   // un Coche TIENE un Motor
}

5. Polimorfismo

Polimorfismo significa que un mismo tipo de referencia puede comportarse de formas distintas según el objeto real que contiene. En Java se consigue mediante herencia y sobreescritura de métodos.

// Clase padre
public class Animal {
    protected String nombre;

    public Animal(String nombre) {
        this.nombre = nombre;
    }

    public void hacerSonido() {
        System.out.println(nombre + " hace un sonido.");
    }
}

// Clases hijas con comportamiento distinto
public class Perro extends Animal {
    public Perro(String nombre) { super(nombre); }

    @Override
    public void hacerSonido() {
        System.out.println(nombre + " dice: ¡Guau!");
    }
}

public class Gato extends Animal {
    public Gato(String nombre) { super(nombre); }

    @Override
    public void hacerSonido() {
        System.out.println(nombre + " dice: ¡Miau!");
    }
}

public class Vaca extends Animal {
    public Vaca(String nombre) { super(nombre); }

    @Override
    public void hacerSonido() {
        System.out.println(nombre + " dice: ¡Muuu!");
    }
}

Polimorfismo en acción

// La variable es de tipo Animal, pero el objeto real puede ser cualquier subclase
Animal a1 = new Perro("Rex");
Animal a2 = new Gato("Misu");
Animal a3 = new Vaca("Lola");

a1.hacerSonido();   // Rex dice: ¡Guau!  — ejecuta la versión de Perro
a2.hacerSonido();   // Misu dice: ¡Miau! — ejecuta la versión de Gato
a3.hacerSonido();   // Lola dice: ¡Muuu! — ejecuta la versión de Vaca
Clave: el tipo de la variable (Animal) decide qué métodos están disponibles. El tipo del objeto real (Perro, Gato...) decide qué versión del método se ejecuta.

Polimorfismo con listas

La utilidad real del polimorfismo se ve cuando trabajas con colecciones:

import java.util.ArrayList;

ArrayList<Animal> animales = new ArrayList<>();
animales.add(new Perro("Rex"));
animales.add(new Gato("Misu"));
animales.add(new Vaca("Lola"));
animales.add(new Perro("Toby"));

// Un solo bucle, cada animal hace su sonido correcto
for (Animal a : animales) {
    a.hacerSonido();
}

// Salida:
// Rex dice: ¡Guau!
// Misu dice: ¡Miau!
// Lola dice: ¡Muuu!
// Toby dice: ¡Guau!

6. Clases abstractas e interfaces

Clase abstracta

Una clase abstracta no se puede instanciar directamente. Define una estructura base que las subclases deben completar.

public abstract class Figura {
    protected String color;

    public Figura(String color) {
        this.color = color;
    }

    // método abstracto — las subclases OBLIGATORIAMENTE deben implementarlo
    public abstract double calcularArea();

    // método normal — se hereda tal cual
    public void mostrarColor() {
        System.out.println("Color: " + color);
    }
}

public class Circulo extends Figura {
    private double radio;

    public Circulo(String color, double radio) {
        super(color);
        this.radio = radio;
    }

    @Override
    public double calcularArea() {
        return Math.PI * radio * radio;
    }
}

public class Rectangulo extends Figura {
    private double base, altura;

    public Rectangulo(String color, double base, double altura) {
        super(color);
        this.base   = base;
        this.altura = altura;
    }

    @Override
    public double calcularArea() {
        return base * altura;
    }
}

// Uso con polimorfismo
Figura f1 = new Circulo("rojo", 5);
Figura f2 = new Rectangulo("azul", 4, 6);

System.out.println(f1.calcularArea());  // 78.53...
System.out.println(f2.calcularArea());  // 24.0

Interface

Una interface define un contrato: qué métodos debe tener una clase, sin decir cómo los implementa. Una clase puede implementar varias interfaces.

public interface Volador {
    void volar();   // todas las clases que implementen esto deben definir volar()
}

public interface Nadador {
    void nadar();
}

// Una clase puede implementar varias interfaces a la vez
public class Pato extends Animal implements Volador, Nadador {

    public Pato(String nombre) {
        super(nombre);
    }

    @Override
    public void volar() {
        System.out.println(nombre + " está volando.");
    }

    @Override
    public void nadar() {
        System.out.println(nombre + " está nadando.");
    }

    @Override
    public void hacerSonido() {
        System.out.println(nombre + " dice: ¡Cuac!");
    }
}

Diferencias clave

Clase abstractaInterface
Puede tener atributosSíSolo constantes
Puede tener constructorSíNo
Puede tener métodos con cuerpoSíSolo con default
Herencia múltipleNo (solo una clase padre)Sí (varias interfaces)
Cuándo usarlaClases relacionadas con código comúnCapacidades compartidas entre clases no relacionadas

7. Ejemplo completo — Sistema de empleados

Un ejemplo que combina herencia, composición y polimorfismo:

// Interface
public interface Evaluable {
    String evaluarRendimiento();
}

// Clase independiente para composición
public class Departamento {
    private String nombre;
    private String ubicacion;

    public Departamento(String nombre, String ubicacion) {
        this.nombre    = nombre;
        this.ubicacion = ubicacion;
    }

    public String getNombre() { return nombre; }
}

// Clase padre abstracta
public abstract class Empleado implements Evaluable {
    protected String nombre;
    protected double salario;
    protected Departamento departamento;   // composición

    public Empleado(String nombre, double salario, Departamento departamento) {
        this.nombre       = nombre;
        this.salario      = salario;
        this.departamento = departamento;
    }

    public abstract double calcularBonus();   // cada tipo calcula distinto

    public void mostrarInfo() {
        System.out.println("Empleado: " + nombre);
        System.out.println("Salario:  " + salario);
        System.out.println("Depto:    " + departamento.getNombre());
        System.out.println("Bonus:    " + calcularBonus());
        System.out.println("Evaluación: " + evaluarRendimiento());
    }
}

// Subclase 1
public class Desarrollador extends Empleado {
    private int proyectosCompletados;

    public Desarrollador(String nombre, double salario,
                         Departamento dep, int proyectos) {
        super(nombre, salario, dep);
        this.proyectosCompletados = proyectos;
    }

    @Override
    public double calcularBonus() {
        return salario * 0.10 * proyectosCompletados;
    }

    @Override
    public String evaluarRendimiento() {
        return proyectosCompletados > 3 ? "Excelente" : "Aceptable";
    }
}

// Subclase 2
public class Comercial extends Empleado {
    private double ventasTotales;

    public Comercial(String nombre, double salario,
                     Departamento dep, double ventas) {
        super(nombre, salario, dep);
        this.ventasTotales = ventas;
    }

    @Override
    public double calcularBonus() {
        return ventasTotales * 0.05;
    }

    @Override
    public String evaluarRendimiento() {
        return ventasTotales > 50000 ? "Sobresaliente" : "Normal";
    }
}

// Main — polimorfismo en acción
public class Main {
    public static void main(String[] args) {
        Departamento ti      = new Departamento("Tecnología", "Madrid");
        Departamento ventas  = new Departamento("Ventas", "Barcelona");

        ArrayList<Empleado> empleados = new ArrayList<>();
        empleados.add(new Desarrollador("Ana",   35000, ti,     5));
        empleados.add(new Desarrollador("Luis",  32000, ti,     2));
        empleados.add(new Comercial("Marta",     28000, ventas, 80000));
        empleados.add(new Comercial("Carlos",    28000, ventas, 30000));

        for (Empleado e : empleados) {
            e.mostrarInfo();       // cada uno calcula su bonus y evaluación
            System.out.println("---");
        }
    }
}
